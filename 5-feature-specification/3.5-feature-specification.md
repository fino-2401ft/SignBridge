## 1. Authentication Lifecycle

### FR-001: User Registration

**Behavior Contract**

Register accepts email, password, and password confirmation in the UI. Email must be syntactically valid (RFC 5322); password must meet minimum 8 characters with mixed case and number; confirmation must match password exactly before submission.

**Success Path**
1. User opens app → Auth screen displays
2. User taps "Sign Up" → Registration form appears with email, password, confirm password fields
3. User enters valid email, password ≥ 8 chars, matching confirmation
4. User taps "Register" → Loading indicator appears, submit button disabled
5. Firebase Auth creates account → Firestore user document created with role: "user", xp: 0
6. System navigates to Login screen with email pre-filled
7. Toast displays "Registration successful"

**Failure Paths**

| Error | Condition | Response |
|-------|-----------|----------|
| E1 | Email format invalid | Inline error below email field: "Invalid email format" |
| E2 | Password < 8 chars | Inline error: "Password must be at least 8 characters" |
| E3 | Passwords don't match | Inline error on confirm field: "Passwords do not match" |
| E4 | Email already exists | Inline error: "Email already in use" |
| E5 | Network error | Toast: "Connection error. Please try again." |

**Recovery Behavior**
- Form values preserved on error (except passwords cleared for security)
- User can retry immediately without re-entering email

**Persistence**
- Session stored in Firebase Auth (30-day expiry)
- On successful registration, redirect to Login (not auto-login)

---

### FR-002: User Login

**Behavior Contract**

Login accepts email/password, prevents duplicate submit while pending, reports invalid credentials at form level, and opens the user's home screen after success. Protected access with an invalid or expired session returns to Login.

**Success Path**
1. User enters valid email and password
2. User taps "Login" → Button disabled, loading indicator shown
3. Firebase Auth validates credentials
4. Auth state synchronized to Zustand store
5. User data loaded from Firestore
6. Navigation to Home screen (Learning Path list)

**Failure Paths**

| Error | Condition | Response |
|-------|-----------|----------|
| E1 | Invalid credentials | Form-level error: "Invalid email or password" |
| E2 | Network timeout | Toast: "Connection error. Check your network." |
| E3 | Too many attempts | Form disabled for 30s, countdown displayed |

**Recovery Behavior**
- Email field preserved on error, password cleared
- Auto-login from valid session before showing Login screen

**Persistence & Authorization**
- Auth token stored by Firebase Auth SDK
- Auth state persists across app restarts
- On app launch, check auth state before rendering Login or Home

## 2. Learning Path & Lesson Lifecycle

### FR-003: Learning Path Display

**Behavior Contract**

The app displays all learning paths in ascending order by the `order` field. Each path shows title, thumbnail, progress percentage, and lock state. Locked paths are visually distinct and non-interactive until unlock conditions are met.

**Success Path**
1. Authenticated user opens app or navigates to Home
2. System fetches learning paths from Firestore collection `learningPaths`
3. System fetches user's progress from `users/{userId}/progress`
4. Paths rendered in order, with:
   - Locked paths: grayed overlay, lock icon, unlock hint text
   - Unlocked paths: thumbnail visible, progress bar, "Continue" or "Start" button

**Unlock Condition Types**

| Type | Rule |
|------|------|
| `none` | Always unlocked |
| `path_complete` | Previous path progress = 100% |
| `xp_threshold` | User total XP ≥ required threshold |

**Failure Paths**

| Error | Condition | Response |
|-------|-----------|----------|
| E1 | Firestore read timeout | Skeleton loading → Error state with retry button |
| E2 | Empty learning paths | Empty state: "No learning paths available" + illustration |

---

### FR-004: Lesson Video Playback

**Behavior Contract**

A lesson displays a video demonstrating an ASL gesture. The user can play/pause/seek. "Mark as Completed" awards XP and updates progress. XP failure has retry logic; lesson is still marked complete.

**Success Path**
1. User taps a lesson in a learning path
2. System loads video from Cloud Storage URL
3. Video displays with controls: play/pause button, seek bar, replay button
4. Gesture description shown below video
5. User watches video (can skip via "Skip")
6. User taps "Mark as Completed" → XP awarded, progress updated
7. Success animation plays (confetti + XP "+10 XP")
8. Next lesson unlocked (if any)
9. User returned to path view or offered to continue

**XP Award Failure Recovery**
1. System attempts to award XP
2. If Firestore write fails → retry once after 1 second
3. If retry fails → mark lesson complete, log XP as pending sync
4. User sees completion animation regardless of XP status

**Failure Paths**

| Error | Condition | Response |
|-------|-----------|----------|
| E1 | Video load failure | Placeholder image + text description, "Retry" button |
| E2 | Network loss during playback | Pause, show "Connection lost" banner |

**Persistence**
- Completed lessons stored in `users/{userId}/progress.completedLessons` (array)
- XP stored in `users/{userId}/xp`
- Video URLs cached locally for offline playback (Expo AV cache)

## 3. ASL Dictionary Lifecycle

### FR-005: Dictionary Search

**Behavior Contract**

Dictionary provides full-text search across gesture vocabulary. Search is case-insensitive and supports prefix matching and fuzzy match (typo tolerance). Results display as cards with video thumbnail, word, and category.

**Success Path**
1. User taps search bar on Dictionary screen
2. Keyboard appears, placeholder "Search gestures..."
3. User types query (minimum 1 character)
4. Results update in real-time (debounced 300ms)
5. Matching gestures display as cards with thumbnail, word, category badge
6. User taps card → Detail screen opens with full video

**Search Match Priority**

| Priority | Match Type | Example |
|----------|-----------|---------|
| 1 | Exact match | "hello" matches "hello" |
| 2 | Prefix match | "he" matches "hello" |
| 3 | Contains | "llo" matches "hello" |
| 4 | Fuzzy (Levenshtein ≤ 1) | "helo" matches "hello" |

**Failure Paths**

| Error | Condition | Response |
|-------|-----------|----------|
| E1 | No results | Empty state: "No results for '[query]'" + suggestions |
| E2 | Search error | Toast: "Search failed" + retry |

**Persistence**
- Dictionary data cached in Zustand store
- Search is session-only (no saved searches)

## 4. Practice Room (AI) Lifecycle

### FR-006: Split-Screen Practice

**Behavior Contract**

Practice room displays sample video on top half and live camera on bottom half. AI continuously processes camera frames, extracts hand landmarks via MediaPipe, runs inference via TFLite, and returns confidence score within 100ms.

**Success Path**
1. User selects gesture to practice from list
2. Camera permission requested (if not granted)
3. Split-screen layout renders:
   - Top: Sample video (autoplay, replay button)
   - Bottom: Camera preview with hand landmark overlay
4. AI processing pipeline runs continuously at ≥ 30 FPS
5. Real-time score displays as confidence percentage + color-coded feedback
6. User practices gesture, sees immediate feedback
7. User taps "End Practice" → Session summary shown
8. Practice record saved to Firestore

**AI Processing Pipeline**

```
Frame → Preprocess → MediaPipe Hand Landmarker → 21 landmarks (x,y,z) 
→ TFLite Inference → Prediction (label + confidence) → Score 
→ UI Update (all within 100ms)
```

**Scoring Algorithm**

```typescript
function calculateScore(prediction: Prediction, landmarks: Landmark[]): number {
  const baseScore = prediction.confidence * 100;
  const visibilityPenalty = avgVisibility(landmarks) < 0.7 ? 10 : 0;
  const stabilityBonus = isStableGesture(prediction, 5) ? 5 : 0;
  return Math.min(100, Math.max(0, baseScore - visibilityPenalty + stabilityBonus));
}
```

**Feedback Thresholds**

| Score Range | Message | Color |
|------------|---------|-------|
| ≥ 80% | "Great!" | #27AE60 (green) |
| 50-79% | "Good, try again" | #F39C12 (yellow) |
| < 50% | "Keep practicing" | #E74C3C (red) |

**Failure Paths**

| Error | Condition | Response |
|-------|-----------|----------|
| E1 | Camera permission denied | Full-screen prompt with settings link |
| E2 | Hand not detected | "Hand not detected" message + hand icon illustration |
| E3 | Poor lighting | Warning banner: "Improve lighting for better recognition" |
| E4 | AI inference timeout | Skip frame, continue processing next frame |

**Persistence**
- Practice records stored: `{ userId, gestureId, score, timestamp, duration }`
- Last practiced gesture remembered for quick retry

**Performance Requirements**
- End-to-end latency: < 100ms
- Camera frame rate: ≥ 30 FPS
- Memory usage: < 150MB

## 5. Real-Time Translation Lifecycle

### FR-007: ASL to Text Translation

**Behavior Contract**

Translation screen provides continuous ASL recognition. Detected gestures accumulate as words in a text buffer. Text is session-only and clears on screen close or user action.

**Success Path**
1. User taps "Translate" tab
2. Camera permission requested (if needed)
3. Full-screen camera view with text output area at bottom
4. AI continuously recognizes gestures:
   - Single gesture → add word to buffer
   - Same gesture repeated → append to current word
   - Hand lowered/out of frame > 1s → add space
5. Text buffer displays accumulated translation
6. User actions:
   - Tap speaker icon → TTS reads full text
   - Tap copy icon → text copied, toast "Copied"
   - Tap clear icon → buffer cleared
7. On screen close → buffer cleared automatically

**Recognition Behavior**
- Word boundary: gesture held for > 500ms = complete word
- Accumulated text scrolls automatically as new words added

**Failure Paths**

| Error | Condition | Response |
|-------|-----------|----------|
| E1 | Camera permission denied | Same as FR-006 E1 |
| E2 | TTS failure | Toast: "Speech unavailable" |

**Persistence**
- Text buffer is session-only (cleared on close or clear action)
- No persistent storage of translated text

## 6. Flashcard Lifecycle

### FR-008: Flashcard Review

**Behavior Contract**

Flashcard (hereafter "card") displays gesture word on front. Tap flips to reveal video. Swipe right marks as "mastered"; swipe left marks as "unmastered". Session tracks mastered/unmastered counts. On completion, summary displays with option to review unmastered cards again.

**Card Structure**
- Front: Gesture word (text), tap hint icon
- Back: Video demonstration, gesture description, swipe hints

**Success Path**
1. User taps "Flashcard" on a learning path
2. System checks for existing session (partially reviewed deck)
3. If partial: modal asks "Continue?" or "Start Over"
4. First card displays (front side)
5. User taps → 3D flip animation reveals back (video)
6. User swipes:
   - Right: Card marked "Mastered", count updated, next card
   - Left: Card marked "Unmastered", added to review queue, next card
7. After all cards reviewed:
   - If unmastered cards exist: "Review unmastered?" modal
   - If all mastered: Celebration screen with stats
8. Session summary: total reviewed, mastered count, percentage

**Resume Behavior**
- Session state saved: `{ deckId, currentIndex, masteredIds[], unmasteredIds[] }`
- Resume available up to 24 hours after last activity
- After 24 hours, session expires and user starts fresh

**Failure Paths**

| Error | Condition | Response |
|-------|-----------|----------|
| E1 | No flashcard data for path | Empty state: "Complete lessons to unlock flashcards" |
| E2 | Video load failure | Show text description only, allow swipe |

**Persistence**
- Session state saved to Firestore
- Resume available within 24 hours

## 7. Authorization & Data Isolation

### FR-009: Protected Access

**Behavior Contract**

All screens except Auth require valid authentication. Invalid/expired session redirects to Login. User can only access their own data. Admin features require role: "admin".

**Auth Guard Logic**

```
IF user is authenticated AND session is valid:
  → Allow access to protected screens
ELSE:
  → Redirect to Login screen
  → Preserve intended destination for post-login redirect
```

**Data Isolation Rules**

| Resource | Access Rule |
|----------|-------------|
| User profile | Only own `users/{userId}` |
| Progress | Only own `users/{userId}/progress` |
| Practice records | Only own records |
| Learning paths | Read-only access to all |
| Admin features | Requires `role: "admin"` in user document |

**Firestore Security Rules**

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
    match /learningPaths/{pathId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && 
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }
  }
}
```

## 8. Error Handling Summary

| Feature | Error Type | User Message | Recovery Action |
|---------|-----------|--------------|-----------------|
| Auth | Invalid credentials | "Invalid email or password" | Clear password, keep email |
| Auth | Network failure | "Connection error" | Retry button |
| Lesson | Video load fail | "Video unavailable" | Retry + text fallback |
| Practice | Camera denied | "Camera permission required" | Settings link |
| Practice | No hand detected | "Hand not detected" | Visual hint overlay |
| Dictionary | No results | "No results for '[query]'" | Show suggestions |
| Flashcard | Video fail | (Silent) | Show text only |

## 9. UI State Requirements

| State | Requirement |
|-------|-------------|
| Loading | Skeleton placeholders, no blank screens |
| Empty | Illustrated empty state + actionable message |
| Error | Error message + retry action, preserve valid form data |
| Disabled | Reduced opacity (0.5), no pointer events |
| Success | Green color (#27AE60), checkmark icon |
| Processing | Button disabled, spinner, no duplicate submits |

---

## 10. Exclusions (Out of Scope for MVP)

- Password reset via email
- Email verification
- Social login (Google, Apple)
- Board sharing / collaboration
- Custom learning paths (user-created)
- Offline mode for video content
- iOS platform
- Non-ASL sign languages
- Text-to-ASL avatar translation
- Push notifications
