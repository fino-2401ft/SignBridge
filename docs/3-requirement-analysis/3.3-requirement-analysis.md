# 3.3 Requirement Analysis - Phân tích Yêu cầu

## Tài liệu này trình bày chi tiết quá trình phân tích yêu cầu cho dự án SIGNBRIDGE, bao gồm các yêu cầu chức năng, phi chức năng, và mô hình hóa hệ thống.

---

## 1. Tổng quan Requirement Analysis

### 1.1. Mục đích

Requirement Analysis là quá trình xác định, tài liệu hóa và xác nhận các yêu cầu của hệ thống từ góc nhìn của tất cả các bên liên quan. Mục tiêu là đảm bảo hệ thống SIGNBRIDGE được xây dựng đúng mục tiêu, đáp ứng đầy đủ nhu cầu người dùng.

### 1.2. Phạm vi phân tích

```
┌─────────────────────────────────────────────────────────────────┐
│                    PHẠM VI PHÂN TÍCH                             │
├─────────────────────────────────────────────────────────────────┤
```

## 2. Xác định Actors và Stakeholders

### 2.1. Primary Actors (Tác nhân chính)

| Actor | Mô tả | Quyền hạn |
|-------|-------|------------|
| **User (Người dùng)** | Người sử dụng chính của ứng dụng | Đăng ký, học, thực hành, tra cứu |
| **Admin (Quản trị viên)** | Người quản lý nội dung | CRUD learning paths, lessons, quizzes |

### 2.2. Secondary Actors (Tác nhân phụ)

| Actor | Mô tả | Vai trò |
|-------|-------|---------|
| **Firebase Auth** | Hệ thống xác thực | Xác thực người dùng |
| **Firestore** | Cơ sở dữ liệu cloud | Lưu trữ dữ liệu |
| **Cloud Storage** | Lưu trữ file | Lưu trữ video, images |
| **TFLite Model** | Mô hình AI | Nhận diện gesture |

### 2.3. Stakeholders Analysis

| Stakeholder | Interest | Expectation |
|-------------|----------|-------------|
| Người khiếm thính | Giao tiếp dễ dàng | Ứng dụng hoạt động realtime, chính xác |
| Người học ASL | Học hiệu quả | Lộ trình rõ ràng, phản hồi nhanh |
| Cộng đồng deaf | Tiếp cận công nghệ | Bảo mật, dễ sử dụng |
| Nhà phát triển | Triển khai thành công | Tài liệu đầy đủ, code clean |
| Giảng viên hướng dẫn | Đánh giá dự án | Sản phẩm hoàn thiện, báo cáo rõ ràng |

## 5. Yêu cầu phi chức năng (Non-Functional Requirements)

### 5.1. Performance Requirements

| Metric | Target | Justification |
|--------|--------|---------------|
| AI inference latency | < 100ms | Đảm bảo realtime feedback |
| Camera frame rate | >= 30 FPS | Video mượt, không lag |
| App cold start | < 3 seconds | UX tốt |
| Video load time | < 2 seconds (4G) | Không chờ lâu |
| Memory usage | < 200MB | Chạy ổn trên thiết bị thấp |
| Battery impact | < 15%/hour | Sử dụng được lâu |

### 5.2. Security Requirements

| Requirement | Implementation |
|-------------|----------------|
| Data privacy | 100% on-device processing cho camera |
| Authentication | Firebase Auth với secure tokens |
| Data isolation | Firestore Security Rules per user |
| No image storage | Frames processed & discarded in RAM |

### 5.3. Usability Requirements

| Aspect | Requirement |
|--------|------------|
| Accessibility | Thiết kế ưu tiên thị giác |
| Navigation | Icon-based, minimal text |
| Touch targets | Min 44pt |
| Feedback | Visual feedback for all actions |
| Error messages | Clear, actionable |

### 5.4. Scalability Requirements

| Aspect | Requirement |
|--------|------------|
| Architecture | Cloud-native, modular |
| Model updates | TFLite hot-reload capable |
| Content updates | Remote config |
| Platform expansion | iOS-ready architecture |

### 5.5. Compatibility Requirements

| Requirement | Target |
|-------------|--------|
| Android version | API 26+ (Android 8.0) |
| Screen sizes | Responsive layout |
| Camera | Front camera required |
| Sensors | Camera permission only |

## 6. Business Rules

### 6.1. Authentication Rules

| Rule | Description |
|------|-------------|
| BR-001 | Email phải là địa chỉ email hợp lệ và chưa tồn tại trong hệ thống |
| BR-002 | Password tối thiểu 8 ký tự, khuyến khích có chữ hoa, số |
| BR-003 | Session expire sau 30 ngày không hoạt động |
| BR-004 | Mỗi user chỉ có 1 session active tại một thời điểm |

### 6.2. Learning Rules

| Rule | Description |
|------|-------------|
| BR-010 | Lesson tiếp theo chỉ được mở khóa khi lesson hiện tại hoàn thành |
| BR-011 | XP được cộng khi lesson hoàn thành (không thể hủy) |
| BR-012 | Flashcard chỉ tạo từ lessons đã hoàn thành |
| BR-013 | Progress được tính: (lessons_hoàn_thành / tổng_lessons) × 100% |

### 6.3. AI/Practice Rules

| Rule | Description |
|------|-------------|
| BR-020 | Practice score >= 80% được coi là "đạt" |
| BR-021 | Mỗi gesture có threshold confidence riêng |
| BR-022 | Practice history lưu tối đa 100 records/user |

### 6.4. Admin Rules

| Rule | Description |
|------|-------------|
| BR-030 | Chỉ user có role="admin" mới truy cập admin features |
| BR-031 | Admin không thể tự xóa tài khoản admin khác |
| BR-032 | Learning path mới phải có ít nhất 1 lesson |
